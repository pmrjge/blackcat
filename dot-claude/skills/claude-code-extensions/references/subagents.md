# Subagent frontmatter and runtime facts (verified against code.claude.com docs, Claude Code 2.1.283)

Frontmatter: `name` (required; no `:`, not starting with `-`), `description` (required), `tools`, `disallowedTools`, `model` (an alias, a full ID or `inherit`; no `$VAR` expansion is documented; this stack's agents name `opus` or `sonnet`, lint-enforced, and the aliases resolve through `ANTHROPIC_DEFAULT_OPUS_MODEL` / `_SONNET_MODEL`, set in stack.env and copied by the installer into settings.json's env, which Claude Code writes over the inherited environment; `ANTHROPIC_DEFAULT_HAIKU_MODEL` holds the Sonnet ID, so background tasks run on Sonnet; a family alias follows the main conversation's exact model when that model is of the same family; a host that sets `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` ignores these variables only in a managed env block), `permissionMode`, `maxTurns` (one turn = one model response, parallel tool calls count once; at the limit the agent stops with no report of its own and a SendMessage resume gets a fresh budget; ignored when the agent is the main thread — all probed on 2.1.283; lint: ≤ 350, < 200 outside orchestrator and main-/ninja-coder, none on blackcat), `skills` (preloads full content — this stack uses none: every agent has the Skill tool and loads skills by their descriptions; lint rejects `skills:`), `mcpServers`, `hooks`, `memory` (`user|project|local`), `background`, `omitClaudeMd`, `effort` (`low…max`; not on Haiku; applies to the agent as a subagent only — as the main thread it runs at the session's level; `ultracode` is not valid here and falls back to the caller's level: ultracode is `--effort ultracode` on a main thread, see `bin/claude-ultracode`), `isolation: worktree`, `color` (red, blue, green, yellow, purple, orange, pink, cyan), `initialPrompt`, `experimental.cacheTtl`.

- `tools` is an allowlist: MCP tools must be listed too (`mcp__<server>`). Exception: every tool of the agent's own inline `mcpServers` is visible whatever the list says, so block individual ones with settings deny rules. On macOS/Linux, Glob and Grep resolve only when Bash is not in the list.
- `Agent(a, b)` type lists are honored only for the main-thread agent (`--agent` / `agent` setting); in subagents this stack's hook enforces the spawn policy (`hooks/agent_guard.py`, POLICY).
- Agent SDK hosts (Claude Desktop's Code tab, Conductor, Nimbalyst, VS Code, Zed) and `claude -p` run with fork mode off: the Agent tool has `run_in_background`, and a subagent does not wait for its background children (their results go to the main conversation). Delegating subagents pass `run_in_background: false`; parallel calls in one message still run concurrently. The main thread must not: a foreground child blocks it for the whole run (the app shows nothing; seen in Claude Desktop 2.1.284 transcripts, `requestShape: "foreground"` in the child's meta.json), so `agent_guard.py` drops BlackCat's `run_in_background: false` (`BLACKCAT_BACKGROUND`). These hosts load user/project/local settings, so `"agent": "blackcat"` applies there too, with the model and effort the host passes for the main thread. `CLAUDE_CODE_EFFORT_LEVEL` overrides every subagent's `effort` (tested); `--effort` and the SDK `effort` option set only the main thread's.
- Main-thread only (removed from subagents, so only BlackCat can use them): Workflow (dynamic workflows), CronCreate/CronList/CronDelete/ScheduleWakeup (in-session scheduling, `/loop`), RemoteTrigger (routines), PushNotification, AskUserQuestion, EnterPlanMode and the other plan-mode tools. Background subagents keep only Read, Grep, Glob, LSP, Bash, Edit, Write, NotebookEdit, WebFetch, WebSearch, Skill, ToolSearch, worktree tools, Monitor, TaskStop, SendMessage, Artifact, plus MCP tools; Agent follows the depth limit. A `context: fork` skill runs as its `agent:` type (skills.md: the field "determines the execution environment (model, tools, and permissions)"); without `agent:` it runs as general-purpose, and the guard refuses every tool call of a generic agent (`generic_agent_reason`). That agent's `tools` list is narrowed by these filters to the main conversation's pool (sub-agents.md, "Available tools"; seen live, CONFIG.md §1 bug 8: `claude-code-guide` forked under a BlackCat without Bash or web tools got only Read, ToolSearch and Skill). So under BlackCat a forked agent gets at most Read, ToolSearch, Skill and the delegation tools its list shares with BlackCat: no Bash, Write, Edit, Glob, Grep, WebFetch, WebSearch or Monitor.
