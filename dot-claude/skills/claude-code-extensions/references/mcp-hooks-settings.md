# MCP, hooks, settings and LSP in this stack (verified against code.claude.com docs, Claude Code 2.1.283)

## MCP lifecycle (on demand, automatic on/off)
1. Local stdio server → inline in ONE agent's `mcpServers` (+ `mcp__<name>` in its tools): starts with the agent, stops when it finishes; its instructions reach that agent only, not its children.
2. Remote HTTP server shared by agents → user scope: `claude mcp add-json -s user <name> '{"type":"http","url":"…","headersHelper":"\"__PYTHON3__\" \"__CLAUDE_DIR__/bin/mcp-headers\""}'` (quoted paths: it runs in a shell; `__PYTHON3__` renders to `<config>/bin/stack-python`, uv's Python 3.13, never a pyenv/asdf shim that may fail in some projects); session-wide; with `MCP_DISCOVERY_CACHE=1` a server with a fresh cache entry connects on first use, otherwise at start in the background; deferred by tool search (on by default on the Anthropic API; leave `ENABLE_TOOL_SEARCH` unset — `true` breaks gateways without `tool_reference` support), callable only by agents naming `mcp__<name>`; its instructions load in the main thread (and in Desktop sessions have been seen in every agent). Keys come from stack.env through the helper, never from config files.
3. Rare servers → disabled entry in the magg catalog (the repo's `dot-claude/magg/config.json`, merged by the installer); mcp-broker mounts and unmounts them and calls their tools for other agents (only mcp-broker has `mcp__magg`). Each broker's magg runs on a private copy of the catalog (`bin/magg-private`), so parallel brokers never switch servers under each other. The catalog tools (`mcp__magg__<prefix>_*`) and magg's list/enable/disable tools are pre-approved; `magg_add_server`, `magg_load_kit` and `proxy` ask the user first.

Reserved server names: `workspace`, `claude-in-chrome`, `computer-use`, `Claude Preview`, `Claude Browser`.

## Hooks
- Events used here: SessionStart (matchers startup|resume|clear|compact|fork), UserPromptSubmit (its `prompt` may be model-authored: a cron fire), UserPromptExpansion (matcher = command name; fires only when a slash command expands, which prompts Claude Code queues itself never do: they carry skipSlashCommands, 2.1.287; input `expansion_type`, `command_name`, `command_args`, `command_source`, `prompt`; `decision: "block"` + `reason` answers the user with no model turn: `/override-agent`), PreToolUse, PostToolUse (Agent|TaskStop), PostToolUseFailure, PermissionDenied (auto mode only), SubagentStart (also on resume; cannot block), SubagentStop, StopFailure (an API error ends the turn; no SubagentStop is promised), SessionEnd (matchers clear|resume|logout|prompt_input_exit|other; SessionEnd hooks share a 1.5 s budget, raised up to 60 s by a longer per-hook `timeout`; side effects only).
- Long work from a hook: start a detached child (`start_new_session`, stdio on `/dev/null`, or the hook waits on its pipes) and exit. The docs only say command hooks run in their own session without a terminal; that a detached child outlives the hook is tested, not documented, so make it restartable. Pattern: `hooks/stack_usage.py` (one collector per session under an `flock`, offsets persisted, restarted by SessionStart/SubagentStart, stopped by a SessionEnd marker or the owner pid's death; CONFIG.md §5).
- A hook that cannot start is a non-blocking error (the gate is silently open), so hook commands run `/bin/sh "__CLAUDE_DIR__/bin/stack-hook" [--fail-closed] <module> [args]` (modules agent_guard, stack_usage, read_gate, web_caps): the launcher finds `bin/stack-python` (uv's Python 3.13; never `/usr/bin/python3`, a bare `python3` or a project venv) and runs `hooks/stack_hook.py` with cached bytecode. `--fail-closed` goes only on the guard's PreToolUse entries: when the hook cannot start they deny (exit 2 or the guard's deny JSON); `STACK_POLICY=off` lifts that except for `no-push`. Never on other events (exit 2 has side effects there) or read_gate/web_caps (fail-open by design). Recovery: `./install.sh`.
- `systemMessage` in the hook's JSON is shown to the user, not the model. PreToolUse decisions go in `hookSpecificOutput.permissionDecision` (`allow|deny|ask|defer`); `updatedInput` replaces the whole input. Inside a subagent, events carry `agent_id` and `agent_type`; no parent id or depth is provided. Frontmatter hooks of the main-thread agent run alongside settings hooks.
- The image limit (`agent_guard.py image-limit`) fails open: PostToolUse `Read|mcp__.*` re-encodes image results above `STACK_IMAGE_MAX_PX` (default 1919) via `updatedToolOutput`, keeping them under the API's 5 MB image cap; PreToolUse `mcp__.*` gives the browser upload tools downscaled copies in a `.downscaled/` folder next to the original via `updatedInput` (image-studio scales its own inputs) and refuses only an oversized image it can't copy; `STACK_IMAGE_UPLOAD_TOOLS` adds tools.

## Settings keys and env used by the stack
`agent`, `autoCompactEnabled`, `autoCompactWindow` (100000–1000000, capped at the model window; `CLAUDE_CODE_AUTO_COMPACT_WINDOW` overrides), env: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (layers below the main thread; default 3, this stack sets 8), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20), `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` (default 200), `MCP_DISCOVERY_CACHE`, `MCP_TIMEOUT`, `MAX_MCP_OUTPUT_TOKENS`. Permission paths: `//abs/path`, `~/path`, `/path` = relative to the settings file; Read denies also block Edit/Write on the path.

## Code intelligence (LSP)
The `LSP` tool is inactive until a plugin declares a language server (`lspServers` inline in `plugin.json`, or `.lsp.json`; strict keys: `command`, `extensionToLanguage`, `args`, `transport`, `env`, `initializationOptions`, `settings`, `workspaceFolder`, `startupTimeout`, `shutdownTimeout`, `restartOnCrash`, `maxRestarts`, `diagnostics`) and its binary is on `PATH`; one server per extension, started on the first edit of a matching file; none in cloud sessions. `claude plugin validate` does not read `.lsp.json`. This stack installs the official `*-lsp@claude-plugins-official` plugins plus its own directory marketplace `agent-stack` (`dot-claude/stack-plugins/` → `~/.claude/stack-plugins/`: haskell, julia, lean, metals); `claude plugin details <name>` lists a plugin's LSP servers, `claude --debug-file` logs `Starting LSP server instance`.
