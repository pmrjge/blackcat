# Claude Code extensions (verified against code.claude.com docs, Claude Code 2.1.283)

Always re-check a key against the raw docs page (`https://code.claude.com/docs/en/<page>.md`: sub-agents, skills, hooks, settings-reference, env-vars, mcp, permissions, plugins/cli-reference, workflows). Unknown fields and keys are ignored silently.

## Subagents (`~/.claude/agents/*.md`, `.claude/agents/*.md`)
Frontmatter: `name` (required; no `:`, not starting with `-`), `description` (required), `tools`, `disallowedTools`, `model` (an alias, a full ID or `inherit`; this stack pins every agent to `claude-opus-5-5` or `claude-sonnet-5-5`, lint-enforced, and runs Claude Code's background tasks on Sonnet 5.5 through `ANTHROPIC_DEFAULT_HAIKU_MODEL=claude-sonnet-5-5`; a host that sets `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` ignores that key in settings files, though the launch environment still applies), `permissionMode`, `maxTurns` (one turn = one model response, parallel tool calls count once; at the limit the agent stops with no report of its own and a SendMessage resume gets a fresh budget; ignored when the agent is the main thread — all probed on 2.1.283; lint: ≤ 350, < 200 outside orchestrator and main-/ninja-/god-coder, none on blackcat), `skills` (preloads full content — this stack uses none: every agent has the Skill tool and loads skills by their descriptions; lint rejects `skills:`), `mcpServers`, `hooks`, `memory` (`user|project|local`), `background`, `omitClaudeMd`, `effort` (`low…max`; not on Haiku; applies to the agent as a subagent only — as the main thread it runs at the session's level; `ultracode` is not valid here and falls back to the caller's level: ultracode is `--effort ultracode` on a main thread, see `bin/claude-ultracode`), `isolation: worktree`, `color` (red, blue, green, yellow, purple, orange, pink, cyan), `initialPrompt`, `experimental.cacheTtl`.
- `tools` is an allowlist: MCP tools must be listed too (`mcp__<server>`). Exception: every tool of the agent's own inline `mcpServers` is visible whatever the list says, so block individual ones with settings deny rules. On macOS/Linux, Glob and Grep resolve only when Bash is not in the list.
- `Agent(a, b)` type lists are honored only for the main-thread agent (`--agent` / `agent` setting); in subagents this stack's hook enforces the spawn policy (`hooks/agent_guard.py`, POLICY).
- Agent SDK hosts (Claude Desktop's Code tab, Conductor, Nimbalyst, VS Code, Zed) and `claude -p` run with fork mode off: the Agent tool has `run_in_background`, and a subagent does not wait for its background children (their results go to the main conversation). Delegating subagents pass `run_in_background: false`; parallel calls in one message still run concurrently. The main thread must not: a foreground child blocks it for the whole run (the app shows nothing; seen in Claude Desktop 2.1.284 transcripts, `requestShape: "foreground"` in the child's meta.json), so `agent_guard.py` drops BlackCat's `run_in_background: false` (`BLACKCAT_BACKGROUND`). These hosts load user/project/local settings, so `"agent": "blackcat"` applies there too, with the model and effort the host passes for the main thread. `CLAUDE_CODE_EFFORT_LEVEL` overrides every subagent's `effort` (tested); `--effort` and the SDK `effort` option set only the main thread's.
- Subagents never get `Workflow`, `AskUserQuestion`, `ScheduleWakeup` or plan-mode tools. Background subagents keep only Read, Grep, Glob, LSP, Bash, Edit, Write, NotebookEdit, WebFetch, WebSearch, Skill, ToolSearch, worktree tools, Monitor, TaskStop, SendMessage, Artifact, plus MCP tools; Agent follows the depth limit.

## Skills (`<dir>/SKILL.md`)
Fields: `name`, `description` (+ `when_to_use`, together ≤ 1,536 chars — put the trigger first), `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork` + `agent` + `background`, `hooks`, `paths`, `shell`. Descriptions are always in context; bodies load when invoked. The listing of all skills gets `skillListingBudgetFraction` (default 0.01) of the context window at ~3 characters per token on current models (4 on older ones): 30K characters on a 1M-context model. Over it, the least-used skills are listed by name only (bundled skills keep their descriptions); this stack keeps 0.01 with descriptions under ~190 characters, `skillListingMaxDescChars: 500` and `skillOverrides` hiding six user-run bundled commands. Frontmatter is YAML: a plain one-line description can't contain `: ` or ` #` — use ` — ` or quote it (`tests/lint_agents.py` checks). `!`cmd`` injection runs through the session's Bash tool — avoid it in skills the blackcat main thread may run; use `context: fork` with an agent that has Bash instead. Model invocation of a skill needs an allow rule to run without a prompt: this stack ships one bare `Skill` rule covering every skill. A description says when to load the skill, never which agent does.

## MCP lifecycle in this stack (on demand, automatic on/off)
1. Local stdio server → inline in ONE agent's `mcpServers` (+ `mcp__<name>` in its tools): starts with the agent, stops when it finishes; its instructions reach that agent only, not its children.
2. Remote HTTP server shared by agents → user scope: `claude mcp add-json -s user <name> '{"type":"http","url":"…","headersHelper":"\"__PYTHON3__\" \"__CLAUDE_DIR__/bin/mcp-headers\""}'` (quoted paths: it runs in a shell; the absolute interpreter, because a pyenv/asdf shim may fail in some projects); session-wide; with `MCP_DISCOVERY_CACHE=1` a server with a fresh cache entry connects on first use, otherwise at start in the background; deferred by tool search (on by default on the Anthropic API; leave `ENABLE_TOOL_SEARCH` unset — `true` breaks gateways without `tool_reference` support), callable only by agents naming `mcp__<name>`; its instructions load in the main thread (and in Desktop sessions have been seen in every agent). Keys come from stack.env through the helper, never from config files.
3. Rare servers → disabled entry in the magg catalog (the repo's `dot-claude/magg/config.json`, merged by the installer); mcp-broker mounts and unmounts them and calls their tools for other agents (only mcp-broker has `mcp__magg`). Each broker's magg runs on a private copy of the catalog (`bin/magg-private`), so parallel brokers never switch servers under each other. The catalog tools (`mcp__magg__<prefix>_*`) and magg's list/enable/disable tools are pre-approved; `magg_add_server`, `magg_load_kit` and `proxy` ask the user first.
Reserved server names: `workspace`, `claude-in-chrome`, `computer-use`, `Claude Preview`, `Claude Browser`.

## Hooks
The image limit (`agent_guard.py image-limit`: PostToolUse `Read|mcp__.*` re-encodes image results above `STACK_IMAGE_MAX_PX`, default 1919, via `updatedToolOutput`; keeps them under the API's 5 MB image cap; PreToolUse `mcp__.*` gives the browser upload tools downscaled copies in a `.downscaled/` folder next to the original via `updatedInput` (image-studio scales its own inputs), and refuses only an oversized image it can't copy; `STACK_IMAGE_UPLOAD_TOOLS` adds tools) fails open. Events used here: SessionStart (matchers startup|resume|clear|compact|fork), UserPromptSubmit, PreToolUse, PostToolUse (Agent|TaskStop), PostToolUseFailure, PermissionDenied (auto mode only), SubagentStart (also on resume; cannot block), SubagentStop, StopFailure (an API error ends the turn; no SubagentStop is promised). A hook that cannot start is a non-blocking error (the gate is silently open): hook commands use an absolute interpreter path (the installer's `__PYTHON3__`), never a bare `python3` that a pyenv/asdf shim may break. `systemMessage` in the hook's JSON is shown to the user, not the model. PreToolUse decisions go in `hookSpecificOutput.permissionDecision` (`allow|deny|ask|defer`), `updatedInput` replaces the whole input. Inside a subagent, events carry `agent_id` and `agent_type`; no parent id or depth is provided. Frontmatter hooks of the main-thread agent run alongside settings hooks.

## Settings keys and env used by the stack
`agent`, `autoCompactEnabled`, `autoCompactWindow` (100000–1000000, capped at the model window; `CLAUDE_CODE_AUTO_COMPACT_WINDOW` overrides), env: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (layers below the main thread; default 3, this stack sets 4), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20), `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` (default 200), `MCP_DISCOVERY_CACHE`, `MCP_TIMEOUT`, `MAX_MCP_OUTPUT_TOKENS`. Permission paths: `//abs/path`, `~/path`, `/path` = relative to the settings file; Read denies also block Edit/Write on the path.

## Code intelligence (LSP)
The `LSP` tool is inactive until a plugin declares a language server (`lspServers` inline in `plugin.json`, or `.lsp.json`; strict keys: `command`, `extensionToLanguage`, `args`, `transport`, `env`, `initializationOptions`, `settings`, `workspaceFolder`, `startupTimeout`, `shutdownTimeout`, `restartOnCrash`, `maxRestarts`, `diagnostics`) and its binary is on `PATH`; one server per extension, started on the first edit of a matching file; none in cloud sessions. `claude plugin validate` does not read `.lsp.json`. This stack installs the official `*-lsp@claude-plugins-official` plugins plus its own directory marketplace `agent-stack` (`dot-claude/stack-plugins/` → `~/.claude/stack-plugins/`: haskell, julia, lean, metals); `claude plugin details <name>` lists a plugin's LSP servers, `claude --debug-file` logs `Starting LSP server instance`.

## Main-thread-only features
Workflow (dynamic workflows), CronCreate/CronList/CronDelete/ScheduleWakeup (in-session scheduling, `/loop`), RemoteTrigger (routines), PushNotification, AskUserQuestion, EnterPlanMode are removed from subagents — only BlackCat can use them.

## Validate
`jq empty <file>` for JSON; `claude plugin validate <dir>` for plugins and agent directories; in the stack repo `uv run tests/lint_agents.py`, `uv run --python 3.12 --with pytest --with httpx --with "mcp>=1.10,<2" pytest -q tests/`, `bash tests/install_smoke.sh`; `/usr/bin/python3 <config>/hooks/agent_guard.py --self-test` (the hooks' own interpreter, as in settings.json); `/doctor` and `/stack-doctor` in a session.

Division of labour: this skill holds the stack's conventions and verified key facts; the built-in `update-config` skill covers the mechanics of editing a settings.json (in this stack, change `dot-claude/settings.json` in the repo, never the live file), `workflow-authoring` covers Workflow scripts, and `skill-creator` covers skill evals and description tuning. Related skills: `mcp-server-craft` (writing an MCP server), `prompt-and-brief-design` (CLAUDE.md, agent and skill prompts), `agent-harness-design` (agent loops outside Claude Code).
