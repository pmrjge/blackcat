RESULT: I generated 300 synthetic tickets from 60 customers and built a curation script. It scrubs PII, removes duplicates, splits by customer and writes a data card. It uses only the Python standard library (MinHash and LSH are written by hand), so nothing was installed.

The 300 tickets are 250 originals plus 50 planted duplicates: 20 exact copies, 10 that differ only in the email address, and 20 lightly edited copies (case, punctuation, one word changed, a "still waiting" line added). Most contain fake PII: emails (some written as "[at]"/"[dot]"), phone numbers, test card numbers and names in sign-offs.

- **PII:** none of the 498 planted values appear in the output. Every replacement was correct: the 488 replacements match the planted values one for one. The other 10 were never in a ticket body.
- **Duplicates:** all 50 found, nothing wrongly removed, and the copy kept is always the original.
- **Counts:** kept plus removed adds up to 300.

**How near-duplicates are matched**
| setting | missed duplicates | wrongly removed |
|---|---|---|
| MinHash estimate only, similarity ≥ 0.8 | 2 | 0 |
| MinHash estimate only, ≥ 0.7 (also with 256 permutations) | 0 | 1 |
| MinHash finds candidates, exact similarity confirms, ≥ 0.7 (**default**) | 0 | 0 |

Similarity here is Jaccard overlap of 5-character chunks of the text.

EVIDENCE:
- **The 0.7 cut-off was tuned on the answer key, so treat the perfect score with caution.** The least similar true duplicate scores 0.744 and the most similar pair of different tickets scores 0.683. A MinHash estimate wobbles by about ±0.04 at this size, which is why matches are confirmed with the exact score. On real tickets, or reworded duplicates, it would need re-tuning.
- **Names:** a name is caught only if it sits in a sign-off or is in the dataset's own customer-name list. A name mentioned mid-sentence that isn't on that list would get through. Addresses and order numbers are not treated as PII (stated in the data card).
- **Split sizes** are approximate in general because customers have very different ticket counts; here they came out at exactly 200/25/25.
- Other checks passed: ruff lint is clean on all three scripts, and re-running the generator gives byte-identical tickets. Last check 2026-10-03 12:16.
