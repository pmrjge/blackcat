RESULT: I drafted the Forgejo units, the Caddyfile and the restic backup and restore-drill setup. Nothing was run or installed, and none of the units went through `systemd-analyze verify`.
- **Forgejo:** `forgejo.service` runs the native binary as user `git` on 127.0.0.1 with hardening, and uses SQLite.
- **Backup:** `forgejo-db-dump.service` writes a consistent SQLite copy. `restic-backup.service` and its nightly timer (03:15, `Persistent=true`) require that dump. Failures go through `notify-failure@.service`.
- **Restore drill:** `restic-restore-drill.service` and a quarterly timer run `scripts/restore-drill`. It checks that the newest snapshot is under 26 h old and that there is free space. It then runs `restic check --read-data-subset=5%` and `restic restore --verify` into a private scratch directory. Next it runs a SQLite `integrity_check` and `git fsck` on every restored repository. Each run appends a line to a history file.
- **Caddyfile:**
  - It binds only to the Tailscale IPv4 address.
  - It takes its certificate for `forge.tailnet-name.ts.net` from the local tailscaled.
  - It proxies to 127.0.0.1:3000 with a health check.
  - SSH goes through `tailscale serve --tcp=2222`, because Caddy owns port 443.
- **Retention:** it is deliberately not in the backup timer. An append-only remote refuses `forget`, so `INSTALL.md` has the command to run on the storage host. That command deletes snapshots, so it is your call.
- **Placeholders:** `tailnet-name`, the restic repository URL and the ntfy and healthchecks endpoints are placeholders to fill in.
