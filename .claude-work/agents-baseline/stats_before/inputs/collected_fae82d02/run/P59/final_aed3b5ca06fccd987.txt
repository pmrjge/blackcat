RESULT: I wrote the hython script and the OCIO/ACES note for Karma. Houdini is not installed on this machine (no `hython`, `hbatch` or `husk` on PATH or under `/Applications`/`/opt`), so the script was only linted and never actually simulated. That means there is no .hip file, no bgeo.sc cache, no timings and no contact sheet yet.

What the script builds, at 1 unit = 1 m:
- **Cloth:** a 2×2 m grid at y = 2, 80×80 rows and columns, triangulated, with Cd = 0.18.
- **Collider:** a polygon sphere of radius 0.6 resting on the ground.
- **Vellum setup:** Vellum Constraints set to Cloth (thickness 0.01, stretch 1e10, bend 0.001), then a Vellum Solver with 5 substeps, 100 constraint iterations, ground plane on.
- **Cache:** a ROP Geometry writes frames 1–120 at 24 fps to `$HIP/cache/vellum_cloth/v###/vellum_cloth.$F4.bgeo.sc`. It always picks the next free version folder and refuses to overwrite one. A File SOP then reads the cache back.
- **Checks after the cache:** every frame file present and non-empty; on the first, middle and last frames, no NaN or Inf in P, nothing below the ground, and the final cloth top between 1.1 and 1.4 m. Results, timings and any parameter names not found on your build go into `sim_report.json` inside the version folder.
- **Licence:** an Apprentice licence stops the script; an Indie licence saves as `.hiplc`.

The note was generated, though without Houdini it only shows "not available" for the session OCIO values. Its main point: Houdini's default Render Working Space is Linear Rec.709, not ACEScg. For an ACES render you set it to ACEScg in the OCIO settings and restart. The note also covers texture file rules, how Karma writes EXR/AOVs in the rendering space, the viewport/MPlay view transform, delivery, and a grey-card check.
