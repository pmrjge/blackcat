Write Go semver module with table and fuzz tests · 2026-10-03 12:11 · go-engineer

The module (`example.com/semver`, go 1.27) is done. Unit tests pass, the 20 s fuzz run passed, and it builds for linux/arm64 and darwin/arm64.

- **Parser:** `Parse(s) (Version, error)` follows SemVer 2.0.0 strictly: no `v` prefix, no whitespace, no leading zeros in the core numbers or in numeric pre-release identifiers, and core numbers must fit in a `uint64`. Every error wraps `ErrInvalid`, and `String()` gives back exactly the string that was parsed.
- **Table test:** `TestParse` has 32 cases (11 valid, 21 invalid). Valid cases also check that `String()` gives back the input.
- **Fuzz test:** `FuzzParse` starts from 11 seed inputs. It checks that:
  - errors always wrap `ErrInvalid`;
  - any accepted input comes back unchanged from `String()`;
  - accepted input has three core parts and only allowed characters;
  - parsing the output again gives the same `Version`.
- **Checks:**
  - `gofmt`, `go vet` and `go test -race` all pass.
  - `go test -fuzz=^FuzzParse$ -fuzztime=20s` ran about 21.3M inputs (~1M/s) with no failures, so no `testdata/` crash files were written.
  - `CGO_ENABLED=0 GOOS={linux,darwin} GOARCH=arm64 go build -o bin/…` succeeded for both targets. Because this is a library with no `main` package, the build output is a `.a` archive rather than an executable. The archive headers say `go object linux arm64` and `go object darwin arm64`.
