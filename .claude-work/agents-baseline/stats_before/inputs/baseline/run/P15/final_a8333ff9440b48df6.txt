## 0. Prerequisites
- **[CREDENTIALS]** A paid Apple Developer Program team and a "Developer ID Application" certificate. The Account Holder creates it, and its private key must be in your login keychain.
- Notarization needs either an App Store Connect API key (`.p8`, key ID and issuer UUID) or an Apple ID with an app-specific password.
- Find the signing identity:
```sh
security find-identity -p codesigning -v
ID="Developer ID Application: Example Corp (TEAMID1234)"   # [CREDENTIALS] your exact identity string, or its SHA-1 hash
```

## 1. Entitlements
A typical GUI app, including Metal and network use, needs none. In that case omit `--entitlements` in step 2.

If you need any, add only the ones required. Save the file as `packaging/myapp.entitlements`: XML plist, LF line endings, no comments.
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <!-- include only what the app needs -->
  <key>com.apple.security.cs.allow-jit</key><true/>
  <key>com.apple.security.cs.disable-library-validation</key><true/>
  <key>com.apple.security.device.audio-input</key><true/>
</dict></plist>
```
Other entitlements you may need:
- `com.apple.security.cs.allow-unsigned-executable-memory`
- `com.apple.security.cs.allow-dyld-environment-variables`
- `com.apple.security.device.camera`
- `com.apple.security.automation.apple-events`

Device and automation entitlements also need the matching `NS*UsageDescription` key in `Info.plist`.

Never include `com.apple.security.get-task-allow`. Notarization rejects it.
```sh
plutil -lint packaging/myapp.entitlements
plutil -lint MyApp.app/Contents/Info.plist
```

## 2. Sign the app (inside-out, hardened runtime, timestamp)
Sign nested code first: frameworks, helpers, XPC services and dylibs. Then sign the app last. Don't use `--deep` when signing. Don't use `sudo`.
```sh
# **[CREDENTIALS]** Uses the private key in your keychain. macOS may prompt for access.
codesign --force --timestamp --options runtime --sign "$ID" \
  MyApp.app/Contents/Frameworks/Foo.framework          # repeat for each nested item

# Nested command-line tools additionally take: -i com.example.myapp.tool

codesign --force --timestamp --options runtime \
  --entitlements packaging/myapp.entitlements --sign "$ID" MyApp.app   # drop --entitlements if none

codesign --verify --deep --strict --verbose=2 MyApp.app
codesign -dvvv MyApp.app          # expect Authority=Developer ID Application, Timestamp, flags=0x10000(runtime)
codesign -d --entitlements - --xml MyApp.app
syspolicy_check notary-submission MyApp.app   # macOS 14+ pre-flight
```

## 3. Notarize the app and staple it
This is the offline-friendly path: notarize and staple the app first, then notarize the DMG separately.
```sh
# **[CREDENTIALS]** Run once per machine. API key route (preferred):
xcrun notarytool store-credentials notary \
  --key AuthKey_ABC123XYZ.p8 --key-id ABC123XYZ --issuer <issuer-uuid>
# Apple ID route instead:
# xcrun notarytool store-credentials notary --apple-id you@example.com --team-id TEAMID1234 --password <app-specific-password>

ditto -c -k --keepParent MyApp.app dist/MyApp.zip
xcrun notarytool submit dist/MyApp.zip --keychain-profile notary --wait   # **[CREDENTIALS]** uploads to Apple
xcrun notarytool log <submission-id> --keychain-profile notary notary-log.json   # read it even if Accepted
xcrun stapler staple MyApp.app
xcrun stapler validate MyApp.app
spctl -a -vvv -t exec MyApp.app      # expect source=Notarized Developer ID
syspolicy_check distribution MyApp.app
```
You can't staple a ZIP, so staple the `.app` and re-zip it if you also ship a ZIP.

## 4. Build the DMG
```sh
rm -rf dist/dmg && mkdir -p dist/dmg
ditto MyApp.app dist/dmg/MyApp.app
ln -s /Applications dist/dmg/Applications
hdiutil create -volname "MyApp" -srcfolder dist/dmg -ov -format UDZO dist/MyApp-1.4.2.dmg
codesign --sign "$ID" --timestamp -i com.example.myapp.dmg dist/MyApp-1.4.2.dmg   # **[CREDENTIALS]** keychain key
hdiutil verify dist/MyApp-1.4.2.dmg
```
For a custom background or icon layout, use `create-dmg` or `dmgbuild`. The result must still be a read-only UDZO image, signed with the Developer ID Application identity.

## 5. Notarize and staple the DMG
```sh
xcrun notarytool submit dist/MyApp-1.4.2.dmg --keychain-profile notary --wait   # **[CREDENTIALS]**
xcrun notarytool log <submission-id> --keychain-profile notary dmg-log.json
xcrun stapler staple dist/MyApp-1.4.2.dmg
xcrun stapler validate dist/MyApp-1.4.2.dmg
spctl -a -t open --context context:primary-signature -v dist/MyApp-1.4.2.dmg
shasum -a 256 dist/MyApp-1.4.2.dmg
```

## Notes
- If you skip step 3 and notarize only the DMG, the service still issues tickets for the nested app. A first launch with no network is then not guaranteed to work.
- Common rejections and fixes:
  - "Signature invalid": something changed the app after signing, so re-sign last.
  - "No secure timestamp": add `--timestamp`.
  - "Hardened runtime not enabled": add `--options runtime`.
  - `get-task-allow` present: remove that entitlement.
- Final test: download the DMG through a browser on a second Mac or user account. `curl` and `scp` don't set the quarantine attribute.
- If you automate this in CI, keep the `.p12`, its password and the `.p8` key in the secret store only.
