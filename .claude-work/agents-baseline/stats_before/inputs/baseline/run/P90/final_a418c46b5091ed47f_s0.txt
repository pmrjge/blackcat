**CLI usage** (installed script `bibfmt`, or `uv run bibfmt`):
```
bibfmt [INPUT] [-o OUTPUT] [--check] [--version]
```
- `bibfmt in.bib -o out.bib` reads `in.bib` and writes `out.bib`.
- `bibfmt in.bib` writes the result to stdout.
- `bibfmt < in.bib > out.bib` goes stdin to stdout; `-` also means stdin or stdout explicitly.
- `bibfmt --check in.bib` writes nothing and exits 1 if the file is not already normalised, including when only duplicate dropping or renaming would change it.
- Exit codes: 0 ok, 1 `--check` found differences, 2 I/O or syntax error with a line number. Warnings go to stderr as `bibfmt: warning: ...`.

**Dedupe policy** (keys compare case-insensitively):
- Same key, same type and same set of (field name, value) pairs counts as identical. Field order, case of type and field names, and runs of whitespace in values are ignored. Later copies are dropped, the first is kept, with a warning.
- Same key but different content counts as conflicting. All distinct variants are renamed `key-a`, `key-b`, `key-c`, … in order of first appearance, using the first spelling of the key as base, with one warning listing the new keys. Nothing is merged. A suffix that collides with an existing key is skipped.
- After renaming, `\cite{key}` no longer resolves.

**Field order** (stable): `author, editor, title, booktitle, journal, series, year, month, volume, number, pages, publisher, organization, school, institution, address, edition, chapter, howpublished, type, note, doi, isbn, issn, eprint, archiveprefix, primaryclass, url, urldate, abstract, keywords`. Unlisted fields follow alphabetically, and repeated fields keep their source order.

**Output format:**
- Entry types and field names are lower-cased, and values are kept raw (braces, quotes, `#` concatenation, macros).
- Entries are written as `@type{key,\n  field = value,\n}` with one blank line between items.
- `@string`, `@preamble`, `@comment` and free text stay in their original position.
- `{}` and `()` entry delimiters are accepted on input, and output uses braces.
- An empty file gives empty output, and the output is idempotent.
