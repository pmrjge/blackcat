**FINDINGS (most severe first):**

- **[HIGH] `P90/src/bibfmt/parser.py:158-167`, `:30`, `:136-143` — `%`-commented-out entries.** The scanner treats every `@` as the start of an entry, and `_NAME` accepts `%` as a field name.
  - A multi-line commented entry rejects the whole file with exit 2. Repro: `%@article{old,\n%  title={x},\n%}\n@misc{a, title={y}}` gives `line 2: expected '=' after field '%' in entry 'old'`.
  - A one-line commented entry is brought back to life and forces a rename of the live entry. Repro: `%@article{k, title={old}}\n@article{k, title={new}}` gives `'%\n\n@article{k-a,…old…}\n\n@article{k-b,…new…}'` plus a warning. The `%` is split onto its own line, so the old entry is no longer commented out for anything that reads `%` as a line comment, and `\cite{k}` stops resolving.
  - Fix: in text between entries, ignore an `@` that follows `%` on the same line and keep those lines verbatim. Add tests for both shapes.

- **[MEDIUM] `P90/src/bibfmt/parser.py:111-113`, `:180-182` — a `"` inside an `@comment{…}` body is treated as the start of a quoted string.**
  - With an odd number of quotes, the scanner swallows the following entries into one verbatim block: they aren't sorted or deduplicated, and `--check` still exits 0 on an un-normalised file. Repro: `@comment{ a 12" record }\n@misc{x, year = 2020, title={y}}\n@comment{ c" }\n` comes back byte-identical, with the fields left unsorted.
  - With a single quote, it fails instead: `@comment{ 12" record }` raises `unterminated string`.
  - Fix: for `comment`, match braces (or parentheses) only and ignore quotes. Add tests.

- **[MEDIUM] `P90/src/bibfmt/parser.py:165-178` — an `@` in ordinary text between entries rejects the whole file.** This contradicts the README's promise that such text is preserved. Repro: `% maintainer: me@example.org\n@misc{a, title={x}}` gives `line 1: expected '{' or '(' after @example`, exit 2.
  - Related, lower impact: `@ misc{…}` (space after `@`) and type names containing digits (`@misc2{…}`) are also rejected.
  - Fix: when `@` isn't followed by an identifier and then `{` or `(`, keep it as text between entries (warn if wanted) instead of raising.

- **[LOW] `P90/src/bibfmt/cli.py:34,44,52` — `--check` ignores CRLF line endings, but formatting doesn't preserve them.** A normalised file with CRLF endings passes `--check` (exit 0), yet `bibfmt f.bib -o f.bib` rewrites it with LF.
