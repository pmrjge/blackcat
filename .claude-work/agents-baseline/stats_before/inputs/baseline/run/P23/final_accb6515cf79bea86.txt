RESULT: I added a PreToolUse hook to a scratch `.claude` directory, separate from `~/.claude` and the stack repo. It blocks Bash commands that run `rm` with both the recursive and force flags, and both sample inputs gave the expected result. It recognises `-rf`, `-fr`, `-Rf`, `-r -f` and `--recursive --force`, including after `sudo`, a full path like `/bin/rm`, or `;`, `&&`, `||`, `|`. To block, it prints a JSON `permissionDecision: "deny"` with a reason and exits 0. For any other command it prints nothing, so the normal permission flow applies. The hook is registered in `settings.json` under `PreToolUse` with matcher `Bash`, run as `/usr/bin/python3 "${CLAUDE_PROJECT_DIR}/.claude/hooks/block_rm_rf.py"` with a 10 s timeout.

One known gap: it does not look inside quoted strings, so `bash -c "rm -rf x"` and `eval '…'` get through. That also means `echo "rm -rf"` is correctly allowed. Other ways of deleting, such as `find -delete` or `rm -r` without `-f`, are also allowed by design.
