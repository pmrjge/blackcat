Two ways work: exit 2 with a message on stderr, or exit 0 with a deny JSON on stdout. I'd use exit 2 for a policy block. Both are from the docs page below. The fetch was truncated before the dedicated PreToolUse section, so I haven't seen that section's own wording.

**Script** (`.claude/hooks/block-rm-rf.sh`, `chmod +x`):

```bash
#!/bin/bash
cmd=$(jq -r '.tool_input.command // ""')
if grep -Eq 'rm[[:space:]]+(-[a-zA-Z]*r[a-zA-Z]*f|-[a-zA-Z]*f[a-zA-Z]*r|--recursive.*--force|--force.*--recursive)' <<<"$cmd"; then
  echo "Blocked: rm -rf is not allowed" >&2
  exit 2
fi
exit 0
```

The regex also catches `-fr`, `-rfv` and `--recursive --force`. A plain `grep -F 'rm -rf'` would miss those.

**Registration** (`settings.json`):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm-rf.sh" }
        ]
      }
    ]
  }
}
```

**Exit codes**
- **Exit 2** blocks the call. Your stderr text is shown as the reason. It overrides any JSON, even an `allow`.
- **Exit 0** means no decision, so the normal permission flow applies. Staying silent does not approve the call.
- **Any other code, including 1,** is a non-blocking error and the command still runs.
- **A missing or non-executable script (exit 127)** is also non-blocking, so the gate is silently off.
- **A timeout** does not block either.

**JSON alternative** (exit 0, stdout must be only this object):

```json
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"rm -rf is not allowed"}}
```

`permissionDecision` can be `allow`, `deny`, `ask` or `defer`. The JSON is ignored if you exit 2, so don't combine them.

**Caveats**
- The command arrives on stdin at `tool_input.command`.
- The handler's `"if": "Bash(rm *)"` field is a best-effort prefilter. It is not hard enforcement, so don't rely on it alone.
- A pattern match can be bypassed by obfuscation such as `eval` or a script that runs `rm`. For hard enforcement, add a `permissions.deny` rule like `Bash(rm -rf:*)` as well.
