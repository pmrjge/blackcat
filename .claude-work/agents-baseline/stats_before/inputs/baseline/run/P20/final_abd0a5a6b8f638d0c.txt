**Driver:** Ubuntu's signed `nvidia-driver-595-open`, the production branch. Blackwell (`sm_120`) only works with the open kernel modules.

**CUDA toolkit:** 13.2 from NVIDIA's `ubuntu2404` repo, and only if you need `nvcc`. 13.2 is the CUDA release paired with the R595 driver.

**PyTorch:** 2.14.1 from the **cu130** index (`https://download.pytorch.org/whl/cu130`). cu132 also works on R595.

Nothing below was run.

### Versions I checked (2026-10-03)
- **Ubuntu driver (noble, from launchpad.net):** `nvidia-graphics-drivers-595` is 595.91.07 in noble-updates and 595.84 in security. 595.99.02 is in -proposed; leave that alone.
- **NVIDIA's apt repo:** its `cuda-drivers` is already at 615.71.09. If you install the `cuda` or `cuda-drivers` metapackages, they will replace Ubuntu's signed driver. Install `cuda-toolkit-13-2` only.
- **PyTorch:** PyPI torch 2.14.1 (2026-09-30) on Linux pins CUDA 13.0.3. The cu130 and cu132 indexes both have 2.14.1 for Python 3.13 and 3.14. A cu134 index exists but has no torch 2.14 wheels.
- **Not checked:** the sandbox blocked NVIDIA's package listing, so I couldn't confirm `cuda-toolkit-13-2` is published. The last `apt-cache policy` line in step 3 checks that.

### 1. Before you start
```bash
lspci -nnk -d 10de::            # GPU present, which driver is bound
mokutil --sb-state              # Secure Boot: Ubuntu's prebuilt modules are signed, no MOK needed
sudo apt update && sudo apt full-upgrade
sudo apt install linux-generic-hwe-24.04   # optional: newer kernel, helps a recent iGPU; reboot into it first
```

### 2. Driver
```bash
sudo ubuntu-drivers list                     # should list nvidia-driver-595-open
sudo ubuntu-drivers install nvidia:595-open
sudo prime-select on-demand                  # hybrid: desktop on the iGPU, dGPU sleeps, CUDA still works
sudo reboot
```
Check after the reboot:
```bash
modinfo -F license nvidia                    # must print "Dual MIT/GPL" (open modules)
nvidia-smi --query-gpu=name,driver_version,compute_cap,memory.total --format=csv   # expect 12.0
nvidia-smi | head -4                         # "CUDA Version" should show 13.2
prime-select query                           # on-demand
cat /sys/bus/pci/devices/$(lspci -D -d 10de:: | awk 'NR==1{print $1}')/power/runtime_status  # "suspended" when idle
```
Run graphics apps on the dGPU with `prime-run <app>` or the desktop's "Launch using dedicated GPU". CUDA needs neither.

### 3. CUDA toolkit (only for nvcc, custom kernels or source builds)
```bash
wget https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb && sudo apt update
apt-cache policy cuda-toolkit-13-2           # confirm it is published before installing
sudo apt install cuda-toolkit-13-2           # never `cuda` or `cuda-drivers`
echo 'export PATH=/usr/local/cuda-13.2/bin:$PATH' >> ~/.bashrc
```
Compile native code for this GPU with `nvcc -gencode arch=compute_120,code=sm_120`. For PyTorch extensions, set `TORCH_CUDA_ARCH_LIST="12.0"`.

### 4. PyTorch (uv)
Add this to the project's `pyproject.toml`:
```toml
[[tool.uv.index]]
name = "pytorch-cu130"
url = "https://download.pytorch.org/whl/cu130"
explicit = true

[tool.uv.sources]
torch = [{ index = "pytorch-cu130", marker = "sys_platform == 'linux'" }]
torchvision = [{ index = "pytorch-cu130", marker = "sys_platform == 'linux'" }]
```
```bash
uv add torch torchvision
uv run python -c "import torch as t; print(t.__version__, t.version.cuda, t.cuda.is_available(), t.cuda.get_device_name(0), t.cuda.get_device_capability(0), t.cuda.get_arch_list())"
# expect 2.14.1+cu130, (12, 0), and sm_120 in the arch list
```
For a one-off install outside a project: `uv pip install torch torchvision --torch-backend=cu130`.

Why cu130 over cu132: it matches the PyPI build, so wheels like flash-attn, vLLM and bitsandbytes are more likely to exist for it. Every package of that kind must be built for the same torch and CUDA version. Choose cu132 only if you need something specific to 13.2. Avoid cu126 and older: those builds don't include `sm_120`.

### Things to avoid
- NVIDIA's `.run` installer, or mixing driver packages from different sources.
- The proprietary (non-open) modules.
- The `graphics-drivers` PPA (R610/615), unless you specifically need a newer branch.

I haven't seen your laptop, so the hybrid-graphics steps assume the usual PRIME layout. If the BIOS has a MUX or dGPU-only mode, that setting is outside Ubuntu.
