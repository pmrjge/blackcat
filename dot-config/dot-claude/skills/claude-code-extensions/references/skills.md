# Skills: fields, listing budget and this stack's layout (verified against code.claude.com docs, Claude Code 2.1.283)

Fields: `name`, `description` (+ `when_to_use`, together ≤ 1,536 chars — put the trigger first), `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork` + `agent` + `background`, `hooks`, `paths`, `shell`. Listed descriptions are in context on every turn (here only `LISTED_CORE`'s; the rest are `name-only`); bodies load when invoked.

Listing budget: the listing of all skills gets `skillListingBudgetFraction` (default 0.01) of the context window at ~3 characters per token on current models (4 on older ones): 30K characters on a 1M-context model. Over it, the least-used skills are listed by name only (bundled skills keep their descriptions). The cut is by usage history, so not deterministic: this stack keeps 0.012 as headroom (`tests/prompt_budget.py` SKILL_BUDGET) and makes the listing lazy with explicit overrides instead: `skillListingMaxDescChars: 250`, `skillOverrides` hiding seven bundled and eight claude.ai user-run commands and the 89 hub modules, and `name-only` for every listed stack skill outside `LISTED_CORE`. `paths:` frontmatter keeps a skill out of the listing until a matching file under the working directory is touched (2.1.287 binary); unused here, since new-file tasks never trigger it.

YAML: a plain one-line description can't contain `: ` or ` #` — use ` — ` or quote it (`tests/lint_agents.py` checks). `!`cmd`` injection runs through the session's Bash tool before the model sees the skill, checked against permission rules only (skills.md, "Permission checks on injected commands"; PreToolUse hooks such as no-push and blackcat-guard are not named there) — keep it out of stack skills; put the command in the body for a Bash call, or use a UserPromptExpansion hook as `/stack-doctor` does. Model invocation of a skill needs an allow rule to run without a prompt: this stack ships one bare `Skill` rule covering every skill.

`skillOverrides` (any settings file; per skill `"on"`, `"name-only"`, `"user-invocable-only"`, `"off"`; skills.md "Override skill visibility from settings"): `"name-only"` lists the name without its description and leaves the skill model-invocable; only `user-invocable-only`, `off` and `disable-model-invocation` take it from the model. Plugin skills ignore it. Lazy listing (`tests/test_skill_modules.py` LISTED_CORE, about 32 cross-domain entry skills): every other listed stack skill is `"name-only"`, found by its name or an agent's Skills line and invoked with the Skill tool, whose result carries the full SKILL.md; its description still must be explanatory (`/skills`, `/` menu, budget fallback). A new skill is `name-only` unless it is a cross-domain entry (then add it to LISTED_CORE). Hub modules (skills named in another skill's table, minus `KEEP_LISTED` in `tests/test_skill_modules.py`) are `"user-invocable-only"`: the Skill tool refuses them, so agents Read `__CLAUDE_DIR__/skills/<name>/SKILL.md`; table rows and agents' Skills lines mark them `name`*, next to one note line per hub (tests enforce both).

Layout: flat dirs `<family>-<topic>` (`rust-async`, `sec-crypto`, `hpc-slurm`). A hub keeps the broad name, ≤ 80 lines: baseline rules plus a `## Modules` table, one line per module. A module SKILL.md stays ≤ 150 lines (core rules and a Verify section) with detail in `references/<topic>.md`, read only when the module says so. Descriptions: ≤ 140 characters, `Load `/`Use ` first, what it covers and when to load it (its hub or siblings where that disambiguates), never which agent loads it. Every skill but a hub is named by a hub's Modules table, another skill, an agent's `## Skills` line or the rules (`STANDALONE` in the test exempts general skills). A new skill gets its directory and its hub row together; merging a skill into another keeps every fact (in the target or its references) and updates the hub table and every cross-reference.

Checks: `tests/test_skill_modules.py` (caps, references, override keys, reachability); `tests/lint_agents.py` (YAML safety, trigger-first, no agent names, listing plus the measured plugin/bundled share within `skillListingBudgetFraction`); `tests/prompt_budget.py --check` gates the listing size.
