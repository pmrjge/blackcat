**Reproducibility caveat.** With the same seed, code and data, the turns and ctx fits gave different draws in different processes:
- v1 run vs attempt 1 on ctx: 0 divergences / R-hat 1.0075 vs 1 / 1.0113.
- Probe vs full run on turns attempt 1: 0 vs 2 divergences.
- spc, static_cc, tool_calls and ctx(n) reproduced exactly between attempts 2 and 3.
- The cause is unverified (candidate: NUMBA-mode kernels compiled differently depending on the PyTensor compile cache).
- Consequences: a gate this close to "0 divergences" can flip between runs of one model, which is why the v2 choices were judged on 4-5 seeds, not on one run. Integration test B1-T11 (tolerance 0) may not be attainable as written (design 9.4).

## 4. Rolling-origin held-out check
- **Protocol** as v1: origin = each session's start, train = rows that ended before it, test = that session's rows.
- **Fold-fit diagnostics.** Fold fits are diagnostic only; no gate reads them.
  - Main run: fold 1 turns 1 divergence (R-hat 1.008), ctx 0; fold 2 0 / 0; fold 3 turns 1 divergence, ctx 0.
  - backtest_clustered run: fold 1 turns 1 divergence, all else 0.
  - v1: fold 1 turns 5, ctx 47.
  - Fold 1 trains on a single session, where the type deviation and the type x session deviation are not separately identified (only their sum is). A residual divergence there is structural.
- **Hit counting.**
  - A test row is a hit when its recorded value exceeds T. A censored row (open, partial near a limit) whose lower bound already exceeds T is a known hit.
  - A censored row below T is unknown. The iid table drops those rows, which leans upward.
  - The session-clustered check treats the observed count as the interval [known hits, known hits + censored rows below T] and compares it with the predictive of K.
  - In that predictive, each posterior draw has one new-session effect shared by all test rows plus one type x session effect per type (design 2).
- **Superseded table.** The clustered table inside `out_v2/tables.md` came from an earlier version of the check that scored uncensored rows only (soft: 4/54, predicted 5.3 [1, 13]). It leaves out the censored hits and is superseded by `out_v2/backtest_clustered/backtest_summary.json`, quoted in section 1. The two runs' iid hit counts are identical.
- **Caveats (unchanged from v1).** n ≤ 65 per family, almost all from one test session. The type x session term was introduced in v1 after a first backtest. The hit rates of the 1–2 % families cannot be verified at this volume.

## 8. Limitations
- 4 sessions, with 66 % of the agent rows in one of them. Only one test session is informative for the held-out check.
- `hit_*`, `window_ctx` and the session row are empty in this data. A collector fix is landing separately, and this analysis does not use it.
  - Because of that, limit stops are inferred through the status_code-1 proxy (design 3.2), and the prompt and session scopes cannot learn.
  - The soft held-out result depends on that proxy, because most of its hits are censored rows.
- The limits in force at past sessions are approximated by the seed in the censoring proxy.
- Sampling is not bit-reproducible across processes for turns and ctx (section 2).
